# PlexonChats 4.0.1 — Bingo Table Renderer & Call Pacing

PlexonChats 4.0.1 is a focused stability and presentation release built directly on stable `v4.0.0` (`657d27766bce60235bc50602b4dd4d14b9e6998c`).

## Bingo table renderer

- Fresh 4.0.1 installations render participant-owned Bingo cards as a fixed-width `TABLE` using `minecraft:uniform`.
- Borders, headers, separators and number cells use deterministic geometry so every vertical divider remains aligned.
- Marked cells remain green without changing visible width.
- Winning cells use color/underline emphasis rather than width-changing bold or marker characters.
- Every number cell remains clickable and run-bound to `/bingo mark <run-id> <number>`.
- `[ CALL BINGO ]` remains run-bound to `/bingo claim <run-id>`.
- `COMPACT` preserves the 4.0.0 borderless renderer as a compatibility fallback.

## Slower configurable calls

- Fresh `data.yml` now uses `draws.interval-seconds: 5`.
- `data.yml` remains the sole gameplay authority for Bingo draw pacing; no competing interval is added to `config.yml`.
- Existing administrator-owned `data.yml` values are preserved. Servers already on 4.0.0 that want the recommended cadence should set `minigames.bingo-classic.draws.interval-seconds: 5` and run `/chat reload`.

## Gameplay authority preserved

4.0.1 does not change the accepted 4.0.0 Bingo mechanics: players explicitly join, own stable personal cards, global draws never auto-mark cells, marks are manual and server-validated, stale run IDs are harmless, and winner/reward/stat completion remains exact-once. Discord remains display-only.

## Compatibility and validation

- `data.yml` schema remains `1`; this polish release does not rewrite existing schema-1 administrator files merely to add new defaults.
- Existing 4.0.0 renderer blocks without `render.style` retain compatibility through their current `show-border` behavior.
- Renderer style, font, dimensions and draw timing are validated before a Bingo definition is accepted.
- Stock full-card rendering remains disabled on every draw to avoid chat flooding.
