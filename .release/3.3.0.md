# PlexonChats 3.3.0

PlexonChats 3.3.0 adds configurable, toggleable Chat Events on top of the accepted 3.2.0 stable communication boundary.

## Chat Events

- Adds five built-in competition types: `TYPE`, `UNSCRAMBLE`, `MATH`, `TRIVIA`, and Unicode-safe `REVERSE`.
- Uses one bounded coordinator and allows at most one active event at a time.
- Supports weighted event selection, per-event cooldowns, minimum-online checks, permission/world audience filters, immediate-repeat avoidance, configurable durations, timeout/cancellation, and manual start/stop/preview.
- Provides independent persistent `chat-events.enabled` and `chat-events.scheduler.enabled` controls, plus runtime pause/resume.
- Uses deterministic normalization controls for case, trimming, whitespace, Unicode normalization, and optional diacritic removal.

## Exact-once winner and rewards

- The first eligible correct answer atomically closes the active competition.
- Exactly one reward bundle is attempted; later answers cannot reopen the event or receive a second reward.
- Reusable reward profiles may combine Vault economy, optional PlexonKeys tiers, and controlled console commands.
- PlexonKeys remains an optional external integration through its Bukkit service boundary and is not bundled into PlexonChats.
- Partial reward-component failure is isolated and logged; it does not select another winner.
- Timeout, cancellation, reload, or master-disable paths grant no reward.

## Chat-source and moderation boundary

- Only genuine accepted native Minecraft public chat can win a Chat Event.
- Console, `/g`/`/l` command sends, `/msg`/`/reply`, Discord-origin messages, auto-messages, connection messages, broadcasts, and synthetic/plugin sends cannot count as competition submissions.
- Existing synchronous cancellable `PlexonChatEvent` moderation remains authoritative before answer acceptance.
- During an active event, a valid answer is checked before stale duplicate-message history so a previously typed event word does not invalidate a legitimate competition answer.
- Outside an active event, the existing public-chat hot path remains unchanged.

## Administration and diagnostics

- Adds `/chat events status|list|enable|disable|pause|resume|start|stop|preview`.
- Adds `plexonchats.events` and `plexonchats.events.manage`, included under the existing admin permission hierarchy.
- Adds a compact Chat Events administration page using the existing holder-routed, permission-rechecked GUI architecture.
- Extends `/chat status` and `/chat diagnostics` with Chat Events scheduler, active-event, reward-integration, and recent-failure state.

## Configuration and compatibility

- Configuration schema advances from v4 to **v5**.
- Existing customized configuration is migrated transactionally and backed up as `config-before-v5-*.yml` before mutation.
- Invalid Chat Events configuration rejects the full reload candidate while preserving the previous known-good runtime snapshot.
- Existing intentionally empty user-owned GUI and auto-message collections remain preserved by migration.
- Existing `PlexonChatsAPI`, synchronous `PlexonChatEvent`, LOCAL/GLOBAL routing, PM/reply, item display, mentions, preferences, auto-messages, DiscordSRV isolation, and transactional reload behavior remain supported.
