# PlexonChats 4.0.0 — Joinable Manual-Mark Bingo & Minigame Data Layer

PlexonChats 4.0.0 is a major Chat Events/Bingo architecture release built from stable `v3.6.2` (`2099d8b50d267b9a430bc1ef34a18415b020318c`).

## Bingo rebuilt around participants

- Scheduled Bingo opens a real join lobby with stock 60/30/15/5 second reminders.
- Players join explicitly through the clickable JOIN action or `/bingo join`; eligible observers are never auto-enrolled.
- Each participant owns one stable traditional 25-number 75-ball card for the run.
- Global calls no longer auto-mark cells.
- Card cells are clickable, run-bound manual mark actions.
- Uncalled cells are rejected through the action bar without changing mark state.
- Successful manual marks render green with fixed width and no `[]` brackets.
- Winner evaluation uses only the claimant's manually marked cells; global draw history alone cannot win.
- Stale click links carry the run UUID and cannot mutate a newer run.
- Exact-one winner/reward/stat completion remains enforced under concurrent claims.
- Admin `/bingo start now` supports one-participant testing without weakening the scheduled production minimum.

## Fixed-width card rendering

The card surface uses `minecraft:uniform` plus configured left padding/cell width/column gaps. Numeric rows retain equal semantic width whether marked or unmarked, correcting the previous alignment drift.

## `data.yml` schema 1

`plugins/PlexonChats/data.yml` is now the administrator-facing gameplay source for:

- Chat Events scheduler/randomizer;
- event enabled states, weights, cooldowns, durations and eligibility;
- TYPE/UNSCRAMBLE/TRIVIA/REVERSE content pools;
- MATH ranges/operations;
- Bingo lobby/card/draw/winning/render gameplay settings.

`config.yml` keeps presentation, reward profile bodies, the master Chat Events enabled switch, and integration credentials/secrets. Runtime cards/marks/deadlines are not written into `data.yml`.

On first v4 startup without `data.yml`, PlexonChats writes `config-before-v4-<timestamp>.yml` and migrates compatible administrator-owned v3.6.2 gameplay values. Existing `data.yml` administrator values are never replaced by stale legacy gameplay settings, and secrets are not copied into the data layer.

## Discord

Discord remains `DISPLAY_ONLY`. Bingo no longer publishes a fake/shared board. The one-message lifecycle now presents shared metadata such as lobby countdown, participant count, last call/draw count, winner and pattern. Discord cannot join, mark, claim or issue rewards.

## Standard Chat Events

TYPE, UNSCRAMBLE, MATH, TRIVIA and REVERSE retain their current rewards, statistics, compact presentation, accepted-channel behavior, timeout/cancel handling and Discord synchronization.
