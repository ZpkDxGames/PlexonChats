# PlexonChats 3.6.0 — Discord Chat Events Embed Synchronization

PlexonChats 3.6.0 adds a production Discord presentation layer for every current Chat Event while preserving Minecraft/PlexonChats as the only authoritative gameplay state.

## Discord Chat Events

- All current event types (`TYPE`, `UNSCRAMBLE`, `MATH`, `TRIVIA`, `REVERSE`, `BINGO`) can publish polished Discord embeds.
- Each event run normally owns one Discord message: start creates it, live state edits it, and winner/timeout/cancel/end edits that same message into terminal state.
- `AUTO` transport prefers DiscordSRV and falls back to a configured webhook; explicit `DISCORDSRV` and `WEBHOOK` modes are also supported.
- DiscordSRV integration targets the repository's supported 1.30.5 shaded JDA API.
- Webhook transport uses asynchronous `wait=true` creation plus PATCH message editing, bounded work, short timeouts and one bounded retry for retryable failures.
- Discord failures are presentation-only: they cannot stop gameplay, delay draws, select winners, duplicate rewards or alter statistics.

## Live Bingo embed

- Bingo keeps the accepted 3.5.0 shared 75-ball model: one authoritative 25-number board, traditional B/I/N/G/O ranges, no FREE center, automatic calls/marks and first-valid-claim victory.
- Discord renders the exact active `BingoRun`; it never generates a separate board.
- Drawn values, last call, draw count, patterns and final winning cells derive from authoritative run state.
- Draws edit one persistent Bingo message instead of flooding the Discord channel.
- Winner, timeout, cancellation and exhaustion produce distinct terminal embed states on that same message.

## Ordering and lifecycle safety

- Live updates are coalesced and processed on bounded asynchronous work.
- Terminal states supersede stale pending live updates; delayed draw callbacks cannot overwrite WINNER/CANCELLED/TIMED OUT.
- Event run IDs isolate consecutive runs from old asynchronous callbacks.
- If an active Discord message was deleted, one safe recreation is allowed; there is no unlimited retry loop.
- Publisher/transports shut down cleanly on reload/disable and do not block Paper shutdown.

## Administration

- `/chat events discord status` reports safe synchronization state.
- `/chat events discord test` emits a marked presentation-only test embed without creating gameplay, rewards or statistics.
- New narrow permission: `plexonchats.admin.events.discord`.
- Chat Events GUI and `/chat diagnostics` expose transport/readiness/channel/message/pending state without exposing webhook credentials.

## Configuration and migration

- Configuration schema advances from v7 to **v8**.
- `chat-events.discord` is the generalized event-sync configuration surface.
- `participation-mode: DISPLAY_ONLY` is mandatory in 3.6.0; Discord-origin messages do not count as event answers or Bingo claims.
- Existing 3.5.0 Bingo webhook URL/username and draw/winner delivery intent are migrated when possible.
- Webhook secrets are preserved during migration and never emitted by normal status/GUI/diagnostics output.
- Administrator-owned event definitions, reward profiles, timers, enabled states and unrelated configuration remain intact.

## Compatibility

Normal LOCAL/GLOBAL chat, PM/reply, scheduled messages, DiscordSRV player-chat synchronization, `PlexonChatsAPI`, synchronous cancellable `PlexonChatEvent`, reward integrations, persistent statistics and accepted 3.5.0 Bingo gameplay remain in place.

Target: Paper 26.2 / Java 25 / PlexonCore 2.0.4.

## Runtime certification

GitHub source/CI/release verification does not substitute for a real PlexonCraft + Discord smoke test. When live host evidence is unavailable during release engineering, provenance records:

```text
runtime_certification=FOLLOW_UP_REQUIRED
```

Required production follow-up includes clean startup, Discord transport readiness, same-message Math completion, same-message Bingo draw/winner/cancel updates, authoritative `/bingo` board parity, exact-once reward/statistics, fallback transport where configured, and webhook-secret non-disclosure.
